Testing Methods

Testing ensures software works correctly. We test with different types of data and look for different types of errors. A well-tested program handles expected, extreme, and unexpected inputs gracefully.

Learning Objectives

  • 12.5.3.2 Perform testing using normal data
  • 12.5.3.3 Perform testing using extreme data
  • 12.5.3.4 Perform testing using erroneous data
  • 12.5.3.1 Describe execution errors at program startup
  • 12.5.3.5 Describe a syntax error in a program code
  • 12.5.3.6 Describe a logic error in a program code

Conceptual Anchor

The Car Safety Test

Before selling a car, manufacturers test it in normal conditions (city driving), extreme conditions (desert heat, icy roads), and erroneous conditions (what if the driver presses gas and brake simultaneously?). Software testing works the same way.

Rules & Theory

Types of Test Data

Data Type Definition Example (age 0–120)
Normal Typical, expected values that should be accepted 25, 16, 45, 70
Extreme (Boundary) Values at the edges of the valid range 0, 1, 119, 120
Erroneous (Invalid) Values that should be rejected -5, 150, "abc", 999

Test Plan Example

Types of Errors

Error Type When Detected Description Example
Syntax Error Compilation / interpretation Code violates language grammar rules print("Hello" — missing )
Runtime Error During execution Program crashes mid-run x = 10 / 0 — division by zero
Logic Error Never (program runs but gives wrong results) Code logic is incorrect average = a + b / 2 instead of (a+b)/2

Error Examples in Python

# SYNTAX ERROR — detected before running print("Hello" # SyntaxError: unexpected EOF while parsing # RUNTIME ERROR — detected during execution age = int(input("Enter age: ")) # user types "abc" # ValueError: invalid literal for int() x = 10 / 0 # ZeroDivisionError: division by zero # LOGIC ERROR — program runs but gives wrong answer def average(a, b): return a + b / 2 # Should be (a + b) / 2 # average(10, 20) returns 20.0 instead of 15.0

Logic Errors are the Hardest to Find

The program doesn't crash and no error message appears — it just produces wrong results. That's why trace tables and systematic testing with known expected outputs are essential.

Common Pitfalls

Only Testing Normal Data

Many students only test with "nice" values. Always test extreme (boundaries) and erroneous (wrong type, out of range) inputs too!

Mixing Up Runtime and Logic Errors

Runtime errors crash the program. Logic errors don't crash — the program runs but gives wrong results. If the program crashes = runtime. If it runs but the answer is wrong = logic.

Tasks

Remember

Define normal, extreme, and erroneous test data with examples.

Apply

Create a test plan (table) for a program that accepts a password between 8 and 20 characters. Include at least 6 tests.

Analyze

Identify the error type in each: (a) pritn("Hello") (b) total = price * quanty where quanty is undefined (c) discount = price * 0.1 when it should be price * 0.15

Self-Check Quiz

Q1: What is extreme (boundary) test data?

Values at the very edge of the valid range. For 0–100: extreme values are 0 and 100.

Q2: Which error type does the program NOT crash for?

Logic error — the program runs fine but produces incorrect results.

Q3: Give an example of a runtime error.

Division by zero (ZeroDivisionError), converting non-numeric string to int (ValueError), accessing a file that doesn't exist.
