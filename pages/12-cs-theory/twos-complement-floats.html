Two's Complement & Floating Point

Computers must represent negative numbers and fractional (decimal) numbers using only binary. Two's complement is the standard method for negative integers, while floating point representation handles fractions and extremely large/small values.

Part 1: Two's Complement

Two's complement is the standard way computers store negative integers. The most significant bit (MSB) acts as the sign bit: 0 = positive, 1 = negative.

Range of Values (8-bit)

Representation Minimum Maximum Range
Unsigned 8-bit 0 255 0 to 2⁸ − 1
Two's complement 8-bit −128 +127 −2⁷ to 2⁷ − 1

Converting to Two's Complement

✓ Method: Convert −45 to 8-bit two's complement

Step 1: Write positive 45 in binary 45 = 00101101 Step 2: Flip all the bits (one's complement) 00101101 → 11010010 Step 3: Add 1 11010010 + 1 ──────── 11010011 Result: −45 in two's complement = 11010011

✓ Converting Back: What is 11010011 in denary?

MSB is 1 → negative number Method 1: Flip & add 1, then negate 11010011 → flip → 00101100 → add 1 → 00101101 = 45 Answer: −45 Method 2: Use negative place value for MSB Place values: -128 64 32 16 8 4 2 1 Binary: 1 1 0 1 0 0 1 1 = -128 + 64 + 16 + 2 + 1 = -45 ✓

Two's Complement Arithmetic

✓ Adding: 35 + (−20) = 15

35 = 00100011 −20 = 11101100 (two's complement of 20) 00100011 + 11101100 ──────── 100001111 ← 9 bits! Discard carry (overflow bit) 00001111 = 15 ✓

✓ Subtracting: 50 − 75 = −25

50 − 75 = 50 + (−75) 50 = 00110010 −75 = 10110101 (two's complement of 75) 00110010 + 10110101 ──────── 11100111 MSB is 1 → negative. Flip & add 1: 11100111 → 00011000 → 00011001 = 25 Answer: −25 ✓

Part 2: Fixed Point Fractions

To represent real numbers, we place an imaginary binary point. The bits to the right of the point represent fractions, halving in value with each step.

Integer Part . Fractional Part
8421 . 1/21/41/81/16
8421 . 0.50.250.1250.0625

✓ Convert 101.110₂ to Denary

Integer part: 101₂ = 4 + 1 = 5 Fraction part: .110₂ = 0.5 + 0.25 = 0.75 Result: 5.75

Part 3: Floating Point Representation

Fixed-point has a limited range. Floating-point overcomes this by using a Mantissa (main digits, precision) and an Exponent (position of the decimal point, range). It works like scientific notation: Mantissa × 2^Exponent.

Component Purpose Analogy
Mantissa Stores the significant digits (precision) The "number part" of scientific notation
Exponent Stores the power (position of binary point) The "× 10ⁿ" part of scientific notation

Decoding Floating Point: The 4 Cases

Rule: If the Mantissa or Exponent starts with a 1, it is negative. Apply Two's Complement (Flip & Add 1) to find its positive magnitude, then apply the minus sign to your calculation.

1 Positive Mantissa, Positive Exponent

Mantissa: 0.1100000 | Exponent: 0011 1. MSBs are 0. Both are positive. 2. Exponent = 0011₂ = 3₁₀. (Shift binary point RIGHT by 3). 3. Mantissa: 0.1100000 → Shift right 3 → 0110.0000 4. Convert to Denary: 0110.0000₂ = 4 + 2 = 6.0 Result: 6.0

2 Negative Mantissa, Positive Exponent

Mantissa: 1.0100000 | Exponent: 0011 1. Mantissa starts with 1 (Negative!). Exponent is 0 (Positive). 2. Find Mantissa magnitude (Flip & Add 1): 1.0100000 → 0.1011111 + 1 = 0.1100000 (Keep the minus sign in mind: -0.11) 3. Exponent = 0011₂ = 3₁₀. (Shift RIGHT by 3). 4. Shift the positive magnitude: 0.1100000 → 0110.0000 = 6.0 5. Apply the minus sign: -6.0 Result: -6.0

3 Positive Mantissa, Negative Exponent

Mantissa: 0.1100000 | Exponent: 1110 1. Mantissa is Positive. Exponent starts with 1 (Negative!). 2. Find Exponent magnitude (Flip & Add 1): 1110 → 0001 + 1 = 0010₂ = 2₁₀. (Since it was negative, shift LEFT by 2). 3. Mantissa: 0.1100000 → Shift left 2 (add zeros) → 0.001100000 4. Convert using Fixed Point weights: 0.125 + 0.0625 = 0.1875 Result: 0.1875

4 Negative Mantissa, Negative Exponent

Mantissa: 1.0100000 | Exponent: 1110 1. Both start with 1. Both are Negative! 2. Mantissa magnitude: 1.0100000 → Flip+1 → 0.1100000 (Remember minus sign) 3. Exponent magnitude: 1110 → Flip+1 → 0010 = 2. (Shift LEFT by 2). 4. Shift magnitude: 0.1100000 → 0.001100000 = 0.1875 5. Apply the minus sign: -0.1875 Result: -0.1875

Normalisation & Trade-offs

Aspect Rule / Effect
Positive Normalised Mantissa must start with exactly 0.1
Negative Normalised Mantissa must start with exactly 1.0
Why normalise? Maximises precision by removing wasted leading zeros. Ensures a unique representation for every number.
Precision vs Range More mantissa bits = more precision (decimal places).
More exponent bits = larger range (bigger numbers). Increasing one decreases the other.

Pitfalls & Common Errors

Forgetting to Add 1 in Two's Complement

The process is: (1) flip all bits, THEN (2) add 1. Forgetting step 2 gives one's complement, not two's complement — you'll be off by 1.

Discarding the Carry in Addition

When adding two values in two's complement and the result has an extra (9th) bit, the carry is discarded — this is normal, not overflow. True overflow is when adding two positives gives a negative, or two negatives give a positive.

Shifting Binary Point Wrong Way

Positive exponent → shift binary point right. Negative exponent → shift left. Getting this backwards gives the wrong value.

Pro-Tips for Exams

Two's Complement Strategy

  • Shortcut: scan from right, keep all bits up to and including the first 1, then flip all remaining bits
  • Always check MSB: 0 = positive, 1 = negative
  • Subtraction = add the negative: A − B = A + (−B)

Floating Point Strategy

  • Always state: mantissa gives precision, exponent gives range
  • Normalisation = mantissa starts 0.1 (positive) or 1.0 (negative)
  • Show your working clearly: convert to fixed point first, then normalise

Q2. Explain the trade-off between the number of bits allocated to the mantissa versus the exponent in a fixed-length floating-point system. [2 marks]
